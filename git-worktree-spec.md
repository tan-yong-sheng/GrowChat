## Acceptance Criteria

- Every HTTP request gets a unique requestId (UUID or nanoid)
- All log entries are structured JSON: `{ requestId, level, message, userId?, timestamp, ... }`
- Severity levels: debug, info, warn, error
- `LOG_LEVEL` env var controls output (default: info; debug in dev)
- Request logging respects LOG_LEVEL — not logged at warn or above
- Error responses include requestId in body for support correlation
- Minimal perf overhead — structured logging must not add >1ms per request on Workers
- Zero remaining `console.log/error/warn/info/debug` calls in `src/`

## Technical Constraints

- No new npm dependencies — use built-in `crypto.randomUUID()` for requestId generation
- Logger must work in Cloudflare Workers runtime (no Node.js APIs like `fs`, `path`)
- Must be compatible with existing `src/services/audit-logging.js` (security audit events) — do not replace those, they serve a different purpose
- Keep the logger utility small — Workers have memory/CPU limits per request
- `LOG_LEVEL` default: `info` in production, `debug` in local dev
